# הצמחים של גדי — static site

A dependency-free static website: Gadi Elasar's weekly nature & bloom posts
from the אלון הגליל Facebook group, aggregated into a calendar-year timeline
(January–December, across years). Plain HTML/CSS/vanilla JS — **no framework,
no build step, no dependencies**. Any web developer can maintain it with a
text editor.

## Structure

```
site/
├── index.html        Page shell (semantic HTML, he/RTL)
├── css/
│   └── styles.css    All styling; theme tokens in :root
├── js/
│   ├── app.js        Entry point: chrome wiring (tabs, back, swipe) + boot
│   ├── core.js       Shared state, helpers and card renderers
│   ├── year.js       Year view (month tiles)
│   ├── month.js      Month view (post timeline)
│   ├── plant-index.js  Plant index view (A–ב)
│   └── plant.js      Single-plant view
├── data/
│   └── posts.json    GENERATED — the posts data (see schema below)
└── images/
    └── <post_id>.jpg GENERATED — one thumbnail per post
```

## Running it

Serve the folder with any static server, e.g.:

```bash
cd site && python3 -m http.server 8000   # → http://localhost:8000
```

Or deploy the folder as-is to any static host (Cloudflare Pages, Netlify,
GitHub Pages, nginx/Caddy on a VPS, S3, …). No server-side code is involved.

## Updating the data

`data/posts.json` and `images/` are generated by `tools/build_site.py`:

```bash
python3 tools/build_site.py   # run from the repo root
```

The script reads the collected source data (the `year_<YYYY>_v3.json` files
and verified CDN maps) from the folder above the repo; point `GADI_SRC` at
another folder if the sources live elsewhere.

The script reads the collected `year_<YYYY>_v3.json` files, writes
`posts.json`, and downloads any missing thumbnails. To add a new year of
posts, add its `year_<YYYY>_v3.json` file and extend the `YEARS` list in
`build_site.py`. Weekly updates work the same way: refresh the year file,
re-run the script, re-upload the folder (only changed files differ).

### posts.json schema

One object per post, sorted by date:

| field     | type           | meaning                                  |
|-----------|----------------|------------------------------------------|
| `id`      | string         | Facebook post id (also the image name)   |
| `date`    | `YYYY-MM-DD`   | post date                                |
| `month`   | number 1–12    | calendar month (drives the timeline)     |
| `caption` | string         | post text (may be empty)                 |
| `plants`  | string[]       | canonical Hebrew plant names             |
| `url`     | string         | link to the original Facebook post       |
| `image`   | string \| null | `images/<id>.jpg`, or null → placeholder |

## Design notes (keep these intact when editing)

- Fully RTL; the timeline spine is a strong green line down the **right**
  side; month names sit beside the line.
- Timeline dots anchor to the **text block below each photo**, not to the
  card's vertical centre (the photo takes most of the card's height, so a
  centred dot would land on the image).
- Year tiles show the month's plant names as chips: first 8 by frequency,
  plus a "+N" overflow chip.
- Month view has a "split by year" toggle (off by default), a floating
  back button, and swipe-right-to-go-back on touch devices.
- The plant index groups names alphabetically with a compact month-range
  label (e.g. `אוק׳–נוב׳`; winter plants wrap the year end: `דצמ׳–מרץ`)
  and a month filter.

## Accessibility & performance

Semantic landmarks, real `<button>`s, focus-visible outlines, lazy-loaded
images (`loading="lazy"`), system font stack, zero external requests —
the site works offline once loaded.
